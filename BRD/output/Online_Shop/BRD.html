Executive Summary

This Business Requirements Document (BRD) provides a comprehensive, factual technical and functional specification for modernizing the Online_Shop Microsoft Access application (Online_Shop.accdb) into an enterprise-grade 3-tier web architecture.

The source database comprises 5 business data tables (Customers, Orders, OrderDetails, Products, Categories), 2 SQL queries (qry_ActiveOrders, qry_CustomerSummary), 3 user forms (frm_MainDashboard, frm_CustomerEntry, frm_OrderProcessing), 1 reports, 1 macros, and 1 VBA code modules, totaling an estimated 420 lines of code (LOC).

The modernized application targets Java 25 and Spring Boot 4.1.0 for stateless backend REST APIs under package com.generated.app, React 19.2.8 for responsive single-page web user interfaces, and PostgreSQL 18 for ACID-compliant relational data storage.

Application: Online_Shop

Migration Objective: Eliminate legacy desktop Microsoft Access dependencies for Online_Shop by converting 5 database tables into PostgreSQL 18 relational schemas with exact data types, transforming 2 queries into Spring Data JPA specifications, porting 3 form views into React 19.2.8 web interfaces, and migrating business logic from 1 VBA modules into Spring Boot service classes.

Current Application

The existing application is a monolithic desktop client file (Online_Shop.accdb) executing on the Microsoft JET/ACE database engine. It packages UI forms (3), reports (1), queries (2), and business logic modules (1) within a single file.

Proposed Modernization

The modernized application is architected as an enterprise 3-tier web platform:
1. Presentation Tier: React 19.2.8 SPA utilizing responsive components, client-side validation, and REST API clients.
2. Application Tier: Spring Boot 4.1.0 (Java 25) REST API controllers, service layer facade, and Spring Security 6 RBAC.
3. Data Tier: PostgreSQL 18 with Flyway database migration versioning and connection pooling.

Expected Benefits

    • High-Concurrency Scaling: Eliminates MS Access file-locking bottlenecks, allowing concurrent multi-user access to Online_Shop.
    • Enterprise Relational Data Integrity: Replaces desktop ACCDB storage with PostgreSQL 18 transactions and Flyway versioned DDL scripts.
    • Modern Web User Experience: Replaces legacy desktop forms (3 forms) with responsive React 19.2.8 single-page web views.
    • Centralized Security & Auditing: Implements stateless JWT authentication, Spring Security 6 RBAC authorization, and TLS 1.3 transit encryption.

Business Problem / Need

The legacy Online_Shop MS Access database (Online_Shop.accdb) exhibits operational vulnerabilities common to desktop file databases: exclusive file-locking bottlenecks during multi-user sessions, risk of database corruption over network shares, inability to enforce granular Role-Based Access Control (RBAC), lack of comprehensive audit logging, and lack of web or mobile browser accessibility.

Current Challenges

    • File Locking & Corruption: Multiple users opening Online_Shop.accdb over local network shares leads to locks and corruption.
    • Storage Limit: MS Access 2GB file size limit restricts long-term transaction growth.
    • Lack of Web/Mobile Support: Desktop Access forms (3 forms) cannot be accessed outside desktop client environments.
