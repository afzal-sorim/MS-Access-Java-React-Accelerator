Executive Summary

This Business Requirements Document (BRD) provides a comprehensive, factual technical and functional specification for modernizing the ConvertedApplication Microsoft Access application (Access_Example_VBA (1) 1.accdb) into an enterprise-grade 3-tier web architecture.

The source database comprises 10 business data tables (excluding 1 internal system/configuration objects) (CMD_LINE_TB, CUM_VAL_TB, DATABASE_STRUCTURE_TB, DECUM_VAL_TB, ROULETTE_TB, TAG_GRP_TB, TAG_NME_TB, tblContacts), 16 SQL queries (101_Object_List_qry, 200_Create_DATABASE_STRUCTURE_TB_qry, 201_Create_DATABASE_STRUCTURE_TB_qry, 202_Add_Constraint_pk001_Primary_Key_PROP_ID_qry, 203_Add_Column_LST_MDFD_ID_qry, 204_Alter_Column_LST_MDFD_ID_qry, 205_Drop_DATABASE_STRUCTURE_TB_qry, 720_Cumulative_Value_qry), 13 user forms (980_Data_Dictionary_frm, 003_Buttons_frm, 004_DSN_Password_frm, 006_Dialogbox_Examples_frm, 700_Create_Filelist_frm, 900_Check_Runtime_frm, 001_About_frm, 005_Access_Security_frm), 8 reports, 3 macros, and 33 VBA code modules, totaling an estimated 13,208 lines of code (LOC).

The modernized application targets Java 25 and Spring Boot 4.1.0 for stateless backend REST APIs under package com.generated.app, React 19.2.8 for responsive single-page web user interfaces, and PostgreSQL 18 for ACID-compliant relational data storage.

Application: ConvertedApplication

Migration Objective: Eliminate legacy desktop Microsoft Access dependencies for ConvertedApplication by converting 10 database tables into PostgreSQL 18 relational schemas with exact data types, transforming 16 queries into Spring Data JPA specifications, porting 13 form views into React 19.2.8 web interfaces, and migrating business logic from 33 VBA modules into Spring Boot service classes.

Current Application

The existing application is a monolithic desktop client file (Access_Example_VBA (1) 1.accdb) executing on the Microsoft JET/ACE database engine. It packages UI forms (13), reports (8), queries (16), and business logic modules (33) within a single file.

Proposed Modernization

The modernized application is architected as an enterprise 3-tier web platform:
1. Presentation Tier: React 19.2.8 SPA utilizing responsive components, client-side validation, and REST API clients.
2. Application Tier: Spring Boot 4.1.0 (Java 25) REST API controllers, service layer facade, and Spring Security 6 RBAC.
3. Data Tier: PostgreSQL 18 with Flyway database migration versioning and connection pooling.

Expected Benefits

    • High-Concurrency Scaling: Eliminates MS Access file-locking bottlenecks, allowing concurrent multi-user access to ConvertedApplication.
    • Enterprise Relational Data Integrity: Replaces desktop ACCDB storage with PostgreSQL 18 transactions and Flyway versioned DDL scripts.
    • Modern Web User Experience: Replaces legacy desktop forms (13 forms) with responsive React 19.2.8 single-page web views.
    • Centralized Security & Auditing: Implements stateless JWT authentication, Spring Security 6 RBAC authorization, and TLS 1.3 transit encryption.

Business Problem / Need

The legacy ConvertedApplication MS Access database (Access_Example_VBA (1) 1.accdb) exhibits operational vulnerabilities common to desktop file databases: exclusive file-locking bottlenecks during multi-user sessions, risk of database corruption over network shares, inability to enforce granular Role-Based Access Control (RBAC), lack of comprehensive audit logging, and lack of web or mobile browser accessibility.

Current Challenges

    • File Locking & Corruption: Multiple users opening Access_Example_VBA (1) 1.accdb over local network shares leads to locks and corruption.
    • Storage Limit: MS Access 2GB file size limit restricts long-term transaction growth.
    • Lack of Web/Mobile Support: Desktop Access forms (13 forms) cannot be accessed outside desktop client environments.
